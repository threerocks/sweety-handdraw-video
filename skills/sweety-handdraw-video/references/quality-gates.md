# 检查与返工

工程检查与观感检查分别记录。`verify` 输出工程结果，并生成实际 MP4 的抽帧；`finalize` 仅在工程结果匹配当前文件且人工/模型检查记录明确通过时生成交付回执。

## 工程检查

- 缺少模型叙事路线判断、美术指导依赖、提示词/简报、图片通过记录或匹配哈希时拒绝生产；图集仅允许已审过的裁切。
- 每个插画像素都有语义部位归属，所有轮廓结束后才填色；描线按部位顺序，上色按部位顺序（`colouring: parts`）或按马克笔颜色跨部位（默认 `markers`：一支笔的颜色涂完再换，部位的上色区间因此重叠，但每个部位的颜料仍在它自己的区间内）；字符按各自起止窗口隔离；实际字形四边须保留空白，不能裁掉字脚或下伸部。笔划间抬笔移位。
- 手臂模式的前臂裁切边位于画布外；仅画笔检查完整笔身、笔尖，以及阴影是否从笔尖起；封面0.0—0.5秒静止，0.5—1.0秒按实际像素渐隐，1秒后才开始旁白。

- 完整解码音视频，核对分辨率、帧率、编码、音画时长差和响度。
- 每条字幕对应实际语音段，分句后的文本逐字保留，时序有序、无越界。字幕采用独立的常规排字层，默认无背景、无手写动画，字形边缘完整。
- 检查最终音轨最后一句没有被截断，并单独看末句后的完成画面与尾音；文件完整不等于收尾自然。
- 字幕时间在 build 时就对着旁白检查（停顿后的字幕起点距语音起点不超过0.3秒），不等渲染；插画、文字等可见像素在字幕显示期间不得进入字幕区（含边距），build 报出压字幕的图和位置。
- 正文元素都在画布内、使用绘制路径，同一主笔事件不重叠；每幅图画完后有看得清的停留，全片笔在画的时间不超过旁白的70%，较严的模式更低（build 的 `pen_busy_share`；`pen_time_share` 拆成描线、上色、揭示、写字、马克笔、抬笔各占多少，揭示不算画）。超限的报错按本片实际画法列出能省的时间：按部位上色比马克笔约省11%，不起形约省28%；如果每页都是“一图加讲解形式”，应改用 `focus_diagram`。
- 人物颜色（`line_first`）：drawing-plan 里每个人物 subject 写 `colours`，包括 `skin`、`hair`（看不见时写 null）和 `clothing`（主衣色，可以列多个），上色提示词逐人写出这些颜色。出图前预检会核对计划里有没有写。build 会实测成图：头部颜料中接近肤色（CIE76 ΔE < 16）的至少要占20%，躯干颜料中接近主衣色的至少要占30%。头发常和墨线一样深、像素又少，所以只要求写明，不做实测。上色后、配准前，用 `drawing_contract.py JOB --colours --plan-id ID --image 上色图` 先查。
  - 阿姨片的两次返工，这项检查都能拦下：产房里的妈妈被涂成片中非洲人物的肤色，头部肤色像素只占0%（正确的图占49%）；退休后的阿姨被参考图带回白大褂，青色开衫只占7%（正确的图占50%）。
- 文字和线稿的显现位置靠近笔尖；每个颜色像素的出现都有真实笔刷覆盖，不允许剩余色块在最后一帧整体补齐。
- 单独检查小面积色块、无彩色填充图、短标点、粗笔画端点、长标题和不同页面数量。不要通过放松断言掩盖路径缺失。
- 图像清理后的元数据与来源属性分别报告，不把隐私处理当作 AI 检测保证。

### 实测观感指标（v1.5，build 自动计算，写入 `timeline.visual_metrics`）

按实际镜头取景、去掉画笔和字幕后渲染的画面计算，不靠估算：

- `first_meaningful_visual_seconds`：屏幕至少1%被画上内容的最早时刻（含1秒封面）。超过3秒警告，超过4秒构建失败；单靠一行标题通常不到0.5%，开场要先画大图或大标题加图。确属有意的慢开场在 `design.json.opening_hook.slow_open_reason` 写明理由，失败降为警告。
- `longest_unchanged_seconds`：画笔落笔、镜头移动、强调动作、翻页都算画面变化；竖屏超过8秒、横屏超过10秒警告。
- 每页 `ink_share`（墨迹占屏比例）、`content_box_share`（内容外框占屏比例）、`ink_under_bottom_ui`（竖屏底部账号/描述区里的墨迹）。插画落进平台底部界面区会警告。
- 字幕：位置默认在平台底部界面之上；手动指定的位置若会被底部界面或右侧按钮挡住，build 给出警告。

这些是找出明显问题的工程指标，不是审美分数；通过不等于好看，仍需看片。

## 观感与内容检查

**开头单独检查。** 按[黄金5秒开场](opening-design.md)实际查看成片0–5秒（包含封面），再连看后续正文，通常至约15秒；短片看至结尾。检查首句是否在实测窗口内传达一个具体理由、画面是否帮助理解、衔接是否继续推进，并定位后文兑现的 beat 和成片时间。受众是否匹配、承诺是否真实和悬念是否兑现写入 `content.evidence`；首帧与可读性写入 `visual.evidence`；绘制顺序与衔接写入 `motion.evidence`。无可用听音时依然保留 `listening:not_done`，不凭字幕或ASR声称开场语气自然。

开场承诺与正文不符、凭空编造反常识或数字、用快速闪切或整块揭示掩盖画不完，须修改对应内容或画面；没有观察证据不能判通过。完整内容保留要求或有意慢开场的例外，须在 `opening_hook.selection_reason` 写明原因和本片的实际判断标准，不为套用5秒方法破坏原意。这些是导演内容与观感审查，现有脚本不会自动判断钩子是否吸引人，也不能据此保证留存率。

查看最终导出文件：全部页面完成图，代表性绘制过程，字幕换行与转场、封面首尾。使用可用播放器检查连续播放；有听音工具时实际听音，没有时用ASR与音轨检查并明确听感未验收。先看画面怎样形成，再看成图是否漂亮：按播放尺寸看，线条应由笔尖带出、先轮廓后上色，不能有整块显现、碎线飞白或灰斑。

记录 `review.json`：

```json
{
  "video_sha256": "实际视频哈希",
  "content": {"status": "pass", "evidence": "事实/限定/来源和字幕已核对；填写开场0–5秒及正文衔接的实际观察、承诺兑现的beat与成片时间"},
  "visual": {"status": "pass", "evidence": "实际看过的帧、时间段及修正结果"},
  "motion": {"status": "pass", "evidence": "实际看过的绘制/上色/转场；说明播放器或连续帧方式"},
  "audio": {"status": "pass", "evidence": "ASR或听音依据，说明最终音轨是否重核"},
  "privacy": {"status": "pass", "evidence": "清理工具、复核结果和残留边界"},
  "continuous_playback": {"status": "pass", "evidence": "用哪个播放器从头到尾播放；或 not_done 并写原因"},
  "listening": {"status": "not_done", "evidence": "本机无音频输出，只做了 ASR 与音轨检查"},
  "limitations": ["未实际完成的听感或其他主观验收"]
}
```

`pass`、`fail`、`not_checked` 必须基于观察，不可由脚本自动填成通过。`continuous_playback` 和 `listening` 单独记录，只能是 `pass` 或 `not_done`（写原因）；`not_done` 时回执状态为 `delivery_review_completed_with_open_checks`，`verification.txt` 写“未完成”，不能并进总的“通过”。用户看后不接受，运行 `handdraw_video.py reject JOB --reason "用户原话"`：回执改为“用户已拒绝，需要返工”，这一版视频不能再 finalize。若只检查了ASR，不能写“已经完整听过”。模型查看抽帧可以验证字形和版面，不能单独证明全片运动流畅。

## 返工规则

先定位问题属于内容、素材、声音、路径还是时间安排；只改对应层。比如字符短笔画跳出，修字形路径；笔触太快，简化画面或增加合理分段；AI图集串入邻图，修裁切或重新生成；读错词，优先重做整篇旁白；确有模型长度限制时先完成声音编辑并核对前后衔接，锁定新的完整母带后重算下游时间线，不能让视频页面成为声音切口。

同一失败连续三次没有改善时改路线或报告具体阻碍。不要无限生成付费素材、把相同失败当新候选，或仅延长视频掩盖机制问题。交付记录保留最终通过证据与仍然未验收的边界。

## 导演终审和声音边界

按随包 omniailab `FILM-ART` 检查每页是否服务讲解、重点是否明确、动作与语音是否冲突、收束是否回应开头。记录实际看到的不足和修正，不能只写“已加载导演 Skill”。艺术动效命中 huashu 时再启用其类型方法，并保留本流程的硬性要求。

所有声音的文件存在、合成成功和 ASR 正确只能证明可用性与文字识别情况；“咬字自然、有情感、适合讲课”需要实际听音判断。无可用听音工具时将 audio 证据写成“文字/音轨检查通过，主观听感未验收”，并在 limitations 和交付说明明确保留这一点。不得自动填写“声音很好”。

代表性连续帧能发现分部位顺序、漏出、突然补色和手臂断边，但稀疏抽帧不能证明逐帧流畅。至少检查所有页面的绘制阶段；有可用播放器时播放完整成片。保留检查范围，不把一条片通过扩展为任意输入都稳定。

部位审查还要检查遮挡：发丝间露出的伞面属于伞，手持物不属于手臂，包与腿相交处按实际前后关系分配。程序只能验证给定归属的执行顺序，不能证明模型分区语义正确。剩余区域只能收纳明确的雨线、地面等辅助元素，不能吞掉头部、手臂或道具主体。

新增选项检查：广告上限16字符且原文未截短；水印原文与换行保留，不抢字幕；已选不重问，每项超时继续；音色同文试听、实际后端、ASR与主观听感分别记录。

## 整篇声音检查

记录旁白原文、生成方式、母带哈希和 alignment 哈希。逐句核对漏读、重读、句尾截断与专有名词；ASR 可疑处另取带前后文的片段复核。检查全部换图点的音轨是否存在新增空白或波形跳变，保留真实换气和语义停顿。不能用一律删静音、缩短所有停顿或全片交叉淡化来掩盖错误。

构建与渲染前验证母带和时间戳哈希，逐样本检查主体旁白未变，只允许封面前和整篇末尾添加静音。混音、AAC编码后重新核对全文与末句；这些工程检查不能代替实际听感验收。改变分页不得改变旁白波形，改变旁白后必须重算画面和字幕。

## 叙事事实必须在图中成立

每幅插画的 drawing-plan 必須列 narrative_requirements：id、原文 narration_quote、可观察条件 observable。引用须来自当前稿；例如“身体切断”需要两处可见空隙与断开的蛇段，“满嘴鲜血”需要咬合处和嘴边可辨识的红色血迹。不能因美术风格克制而抹掉剧情事实。

看实际图，在 drawing-review 的 narrative_checks 中按相同 id 记录 status 与具体 evidence。未检查、失败、漏项、图片哈希变动时，构建拒绝继续。证据必须指出可见位置或关系；“主体正确”“图片存在”不能作为内容通过的理由。工程能约束检查是否完成和证据是否对应当前图，不能自动理解“切断”。

最终解码帧再对照这些条件，防止裁切、遮挡或揭示时间使关键结果消失。默认无背景音乐；核对实际混音输入、完整末句和短片尾，见 audio-and-ending.md。用户指出内容不符时撤回相关通过结论，修正该层，不能用旧通过记录抵消反馈。

## 字幕唯一性是交付硬门槛

同一句旁白在同一时刻只允许显示一份字幕。禁止两套字幕叠加，无论来自画面烘焙、字幕事件、MP4 内嵌字幕轨、网页 `<track>` 或播放器自动加载的字幕文件。默认保留白字、黑色细描边、无底板；用户另选形态时仍执行唯一性门槛。

只从无字幕素材和独立字幕层重新合成，禁止在已有硬字幕成片上叠加第二层。构建和渲染检查 cue 与字幕事件一一对应、角色一致、无时间重叠；交付检查 MP4 无额外字幕轨、同目录无 SRT/ASS/VTT 等字幕文件。编辑字幕只放 `outputs/editing/`，预览页不加字幕轨。最终还须检查实际解码画面的长句、换句和片尾；任何双字幕直接判 FAIL，修正后才能交付。第三方播放器主动开启的自动翻译/实时字幕须单独关闭，不能把未复现的显示来源当成已查明。

## 分镜门槛

生产构建必须有 `storyboard.json`。`storyboard_lint.py` 在生图前检查计划，`build` 按实际时间线硬性拦截：视觉节奏、同图连用、视觉数量与插画比例、镜头类型多样性、计划视觉是否全部绘制、纯文字时长、角色参考引用、绘制窗口是否够画；规则和阈值见[创作与分镜](story-design.md)。警告（窗口短于视频节奏、笔要加速；预估静止段；有角色的插画窗口装不下一个人；按常见图量估算会超出模式的笔忙上限）写入 `timeline.storyboard.warnings`，审片时逐条看实际画面。后两条要在生图前处理，到构建时只剩删图一条路。

不要为过检而注水：用极小标记凑节奏、给同一构图换镜头类型名、把标题拆成多个 text_group，都在导演终审中判 FAIL。宿主不能生图时停止并告诉用户，不交付纯文字片。

## 一眼可辨认

每幅插画的 drawing-plan subject 写 `identity_cues`（缩略图尺寸下靠什么认出它）。出图后运行 `python3 scripts/drawing_contract.py JOB --thumbnails` 生成无字幕的编号缩略图，按编号逐个在1秒内说出名称，再对照计划；写入 drawing-review：

```json
"recognizability": {"status": "pass", "named_as": "一串紫葡萄和藤叶", "evidence": "160px 编号5，不看字幕一眼认出果串"}
```

叫不出、叫错（如把烂葡萄看成无花果）时按 identity_cues 重画，不能靠标题或字幕补救。有 storyboard 的任务缺少这两项时，出图前检查和构建均拒绝继续。
