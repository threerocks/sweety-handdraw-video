# v3.0.0

手绘线的收官版本。和上一个公开版本 v2.0.2 相比，3.0 有三处变化：

- **画法更像人**：先出线稿再上色；笔先起形，按模块描线，用橡皮擦掉起形，最后拿马克笔由浅到深上色。
- **讲解形式成为主角**：清单、表格、流程、地图、公式、自定义机制动画，都按口播的字出现。
- **成片自检后的收官修复**：用户看完 v3 的四部测试片后，又做了一轮竞品对标和逐帧自检，修掉观众看得见的问题。还把每部片都要手写的上千行脚本收进了 Skill，并加上画材质感。

## 1. 像人一样画

- **线稿先行**：先生成纯黑线稿，再拿线稿做上色编辑，由 `line_first.py` 配准。笔画的就是线稿里的每一条线。三张测试图里，笔真正画到的线稿比例从 96.3%、97.2%、77.9% 提高到 100%。
- **画的过程**：
  - 浅蓝色起形；
  - 按模块“外轮廓 → 长结构线 → 细节”描线，模块之间稍停；
  - 橡皮擦掉起形；
  - 按马克笔上色：同色一起涂，先浅后深，底色涂完再压阴影（默认 `drawing.colouring: "markers"`）。
- **画材质感**（新增，`drawing.texture`，默认开）：
  - 墨线：长线的落笔和收笔变细，最细到 40%；线内有很轻的浓淡。
  - 马克笔：两遍重叠处深约 9%，边缘略积色，有淡淡的笔道。
  - 与关闭时的成图相比，颜色平均差 ΔE 1.1–2.1，墨线核心保留 ≥99.96%，不会多出墨。构建时间多约 10%。
  - `texture: false` 回到 2.x 的画法，成图逐字节相同。
- **上色过程不再有台阶毛边**：
  - **原因**：上色前沿是按规划尺寸算的，放大显示时会出现 3–4.5 px 的方块台阶。10-29 只修了成图。
  - **现在**：前沿在显示分辨率下插值，并加 1 px 抗锯齿。两张马克笔样图上：
    - 前沿落在规划格线上的比例从 0.43–0.67 降到 0.25–0.29，已是随机水平；
    - 每 100 px 前沿上 ≥1 px 的台阶，从 7–15 个降到 1.8–7.5 个。

证据：`output/evidence/v3/final/media/`、`output/evidence/v3/line-first/`、`output/evidence/v3/thinking/`。

## 2. 观众看得见的收官修复

| 问题 | 原因 | 现在 | 前后对比 |
|---|---|---|---|
| 水印压到人脸、头和气泡文字（v3 四部都有） | 水印固定在标题下方同一处 | 渲染前每页抽 6 帧，在四角和左右边缘的 18 个位置里挑墨迹最少的；换位置时随翻页淡出淡入；最好的位置压墨仍超过 6%，`verify` 就判失败 | 四部旧片中，水印下墨迹超过 2% 的页从 15 页降到 1 页 |

## 3. 做成别人也能用的

- **制作工具包**：
  - **改了什么**：过去每部片要在 `work/` 手写 10–14 个 Python 文件，共 1,150–1,780 行。现在一部片只写数据：口播 `inputs/script.json`、出图 `design/image-specs.json`、画面 `design/film.json`、封面 `design/cover.json`。
  - **工具**：`codex_image.py`、`art_pipeline.py`、`film_kit.py`、`cover.py`，说明见 `references/production-kit.md`。
  - **复刻验证**：用它重写存款片，代码从 1,155 行变成 234 行数据，编出的 `job.json` 与原片一致，只有几处差异，都是工具包修正了原脚本的错误（5 处口播计时、7 处进度条说明）。
  - 出图路线修了两处画布比例的坑：参考图先补边到所要画幅；上色和线稿编辑按线稿自己的画幅出图。
- **读法和写法分开**：
  - **用法**：`narration.say` 写成 `{"Grok": "格罗克", "70万": "七十万"}` 这样的映射。字幕照原文显示，配音、识别核对和字幕计时都按读法。
  - **配音前先试读**：`voxcpm_voice.py JOB --probe-terms` 把每个英文词、数字放进它所在的句子，试读两次，读不准就给出映射建议。
  - **顺带修复**：识别比对原来区分大小写，读对了的 “amend” 被识别成 “Amend” 也判失败，现在不区分大小写。
- **出图前先算预算**：
  - 简报自带本页的绘制预算，默认按 2:3 竖屏构图。
  - `storyboard_lint.py --budget` 按每张图的画法给出每秒笔数。
  - 人物在 drawing-plan 里写明肤色、发色和衣服颜色，上色后实测。
  - 讲解动效页和章节页也计入“画完可看”的时间。
- **只靠动效讲解的页面可以不放插画**：
  - 这类页面的内容范围、首个可辨画面都会把动效算进去。
  - 竖屏底部 UI 的检查，2:3 片按实际被遮住的高度算。

## 6. 已知限制

- **生图模型不听轮廓数**：交回的线稿笔画数是所要轮廓数的 1.3–6 倍。白描这类细线画风，单张要画 10–16 秒，一分钟片的 7–8 秒页面放不下。历史测试片只画了一张图，其余由讲解形式承担。
- **画面太满时，水印仍可能压墨**：四个角和两侧都被占满的页面没有空位，`verify` 会报错，需要把那页的一角空出来。
- **以上都是工程检查**：连续观感、画材质感是否“像人画”、配乐与音量，需要人工观看和试听。
