# 人像绘画视频：操作手册（给执行任务的模型）

用户给一张人像照片，要一部「一笔一笔画出来」的过程视频：油画、素描或动漫插画。整个流程由一条命令完成，**你不需要、也不应该自己判断坐标、参数或画法**。照着下面做。

## 1. 问清两件事

- **照片路径**。用户粘贴的图片若只显示成文件图标，问用户要文件路径，不要猜。
- **画法**：油画 `oil`、素描 `sketch`、动漫插画 `anime`，或三种都要 `all`。用户没说就问一句。

用户给了背景音乐文件就记下路径（`--music`），没给就不用管，程序会按画法配乐。

## 2. 检查环境（每次会话第一次运行前）

```bash
python3 labs/oil-portrait/make.py setup
```

每行都是 `OK` 才继续。有「缺少」时：
- 缺少人脸关键点环境：这条命令会自动安装（约 700 MB），等它结束再运行一次。
- 缺少 codex、ffmpeg 或引擎环境：告诉用户缺什么，停下，不要自己装别的东西。

## 3. 运行

```bash
python3 labs/oil-portrait/make.py run "照片路径" --kind sketch
```

- **一定要放到后台运行**（Bash 工具的 `run_in_background: true`），不要设超时。一种画法 20–40 分钟，`all` 约 40–60 分钟（三种同时画）。
- 运行期间不要再启动同一张照片的第二个任务。等完成通知；用户问进度时，运行 `python3 labs/oil-portrait/make.py status`，把结果转告用户。
- 有音乐：加 `--music "音乐路径"`。

## 4. 汇报

命令结束时最后会打印「任务 … 完成情况」一段：每种画法的验收结论（PASS/FAIL）、视频路径、`! open …` 观看命令、报告路径，以及没通过的检查项。

- **原样转述这一段给用户**，包括没通过的项。
- 验收 FAIL 时，不能说「已完成」或「效果很好」，要说哪一项没通过、数值是多少。
- 不要描述你没看过的画面细节。

## 5. 出错时

| 输出里看到 | 你做什么 |
|---|---|
| `照片里找不到人脸` | 告诉用户换一张脸部清楚、正面或半侧面的照片 |
| `… 生成 3 次都不合格` | 原命令再运行一次（会从断点继续）；还失败就告诉用户原因那一行 |
| `自动标注五官失败` | 原命令加 `--redo assets` 再运行一次；还失败就告诉用户，建议换照片 |
| `命令失败 … 日志：…` | 把日志路径和最后几行告诉用户。不要改代码 |
| `环境不完整` | 回到第 2 步 |
| 用户说某种画法要重画 | 原命令加 `--redo plan`（重新规划并出片）；只想重出视频加 `--redo film` |

## 6. 不要做的事

- 不要手写或修改五官坐标、`plan.json`、引擎参数；不要直接调用 `paint.py`、`sketch.py`、`anime.py`、`film.py`。
- 不要跳过验收，不要删掉报告里不好看的数字。
- 仓库是公开的：照片、目标画、视频都在 `output/`（不进 git），不要 `git add` 它们，不要推送。
- 不要改 `prompts/` 里的提示词来「适配这张照片」。

## 7. 文件在哪

- 成片：`output/paint/portrait-任务名-画法-日期/`：`film.mp4`（带音乐）、`film-silent.mp4`、成品图、目标画、`cover.png`、`report.md`（验收报告）、`sheet.jpg`（过程缩略图）。
- 工作文件：`output/portrait/任务名/`，日志在 `logs/`。
- 同一张照片生成过的目标画会缓存，换画法或重跑都不会重新生成。
